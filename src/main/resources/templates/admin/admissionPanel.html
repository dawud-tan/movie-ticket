{! The door, one ticket at a time. WHY THE WHOLE PANEL SWAPS AND NOT JUST THE RESULT: the input has to come back empty and focused for the next customer, and an usher with a queue in front of them will not click into a field between scans. Re-rendering the form is what clears it; `autofocus` on the freshly swapped input is what htmx honours to put the cursor back. Swapping only a result div would leave the previous ticket's code sitting in the field, and the next scan would append to it. WHY THERE IS NO POLLING AND NO JAVASCRIPT OF OUR OWN: a scan is caused by a person, not by elapsed time. A barcode scanner types its payload and presses Enter, so a plain form submit is the entire integration — no camera permission, no device API, and it works identically when the code is typed by hand because the customer's phone is flat. A double submit on refresh is harmless here, unlike most POST-renders-HTML: rescanning a token is precisely what `admitted_at IS NULL` makes safe, and the repeat reports ALREADY_ADMITTED rather than admitting anyone twice. THE HEADLINE AND THE MESSAGE ARE TRANSLATED IN JAVA, not here: both come off AdmissionService.ScanResult, which resolves them through the bundle for the request's language the same way ShowtimeResource does. severity stays a raw ok/warn/bad because the stylesheet selects on it — the same split StatusLabels makes for a status badge. !}
